  <files>src/ui/mod.rs</files>
  <action>
Refactor the event loop in src/ui/mod.rs to use tokio::select! with a Message enum:

1. **Create Message enum** (near top of file, after SystemStats):
   ```rust
   #[derive(Debug)]
   enum Message {
       KeyPress(KeyEvent),
       RunnerEvent(RunnerEvent),
       SystemStats(SystemStats),
       FixResult(CheckResult),
       FixAllResult(CheckResult, bool),  // (result, is_last)
       RetryResult(CheckResult),
   }
   ```

2. **Convert keyboard channel to tokio::sync::mpsc**:
   - Change `spawn_keyboard_thread` to return `mpsc::UnboundedReceiver<KeyEvent>` instead of `std::sync::mpsc::Receiver`
   - Use `tokio::sync::mpsc::unbounded_channel()`
   - IMPORTANT: Keep using std::thread for the keyboard thread itself (NOT tokio::spawn) - this ensures keyboard events are captured by OS scheduler even under high Tokio task load
   - Use `blocking_send` from the std::thread to send to the tokio channel

3. **Replace main loop** with tokio::select!:
   - Remove the sleep-based polling loop
   - Use `biased;` to ensure keyboard checked first
   - Each channel becomes a select! branch returning a Message variant
   - Handle all messages through a single `handle_message` function

   Pattern:
   ```rust
   loop {
       let msg = tokio::select! {
           biased;  // Keyboard priority

           Some(key) = key_rx.recv() => Message::KeyPress(key),
           Some(event) = runner_rx.recv() => Message::RunnerEvent(event),
           Some(stats) = stats_rx.recv() => Message::SystemStats(stats),
           Some(result) = fix_rx.recv() => Message::FixResult(result),
           Some((result, is_last)) = fix_all_rx.recv() => Message::FixAllResult(result, is_last),
           Some(result) = retry_rx.recv() => Message::RetryResult(result),
           else => break,  // All channels closed
       };

       if handle_message(&mut app, msg, &channels, &config, ...)? == Action::Quit {
           break;
       }

       if app.needs_redraw {
           terminal.draw(|f| dashboard::render(&app, f))?;
           app.needs_redraw = false;
       }
   }
   ```

4. **Create handle_message function**:
   - Takes Message enum and returns Result<Action>
   - Consolidates all event handling into one match
   - Replaces the scattered try_recv() calls
   - For RunnerEvent: no longer needs rate limiting (select! naturally throttles)
   - For KeyPress: move the existing handle_key_event logic, or call it
   - Sets `app.needs_redraw = true` for all UI-affecting messages

5. **Handle RetryAll specially**:
   - When KeyAction::RetryAll is returned from keyboard handling
   - Need to restart the runner and reassign event_rx
   - Consider using an enum return from handle_message that includes "restart runner" action

6. **Remove obsolete code**:
   - Remove MAX_RUNNER_EVENTS_PER_FRAME constant (no longer needed)
   - Remove FRAME_DURATION constant (no longer sleep-based)
   - Remove the tokio::time::sleep(FRAME_DURATION).await at end of loop

7. **Keep these unchanged**:
   - spawn_stats_worker (already uses tokio::spawn correctly)
   - start_runner function
   - handle_key_event function (can be called from handle_message)
   - All the async operation spawning (fix, retry, etc.)

AVOID:
- Don't convert keyboard thread to tokio::spawn (research shows OS thread is necessary for responsiveness under CPU load)
- Don't use try_recv() in select! branches (use async recv())
- Don't remove the biased; keyword (ensures keyboard priority)
